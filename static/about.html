♟ I am playing chess while you are playing checkers ⛀

PlayRules

I am playing chess while you are playing checkers puts a standard chess army and a checkers army on the same board, and swaps their goals: the chess side wins the way a checkers game is won (clear the board, or leave the opponent no move), and the checkers side wins the way a chess game is won (checkmate). Neither army is built for the job it's been handed — a checkers side has to build a mating net out of pieces that shuffle one square diagonally, and the chess side can't just simplify into a won endgame, because a "won" material position is worth nothing until the board is literally empty. That tension is the whole game.

How it's built

The rules engine is a pure-Python package with no web or UI dependencies at all — it can be imported and played end to end with nothing installed but numpy. The FastAPI service and vanilla-JS frontend you're using right now are one deployment target for that engine; a future training pipeline (self-play, reinforcement learning) is meant to be a peer of this web app, not built on top of it, sharing the exact same rules code so a trained model and the deployed site can never quietly disagree about what a legal move is.

Balance

The 24-checkers-vs-16-chess-pieces starting layout is a first guess, not a playtested balance point — the chess army is far more mobile, and a queen can pick off short-range checkers with little counterplay. Alternate layouts exist and are meant to be compared with the CLI's selfplay and match commands rather than hand-tuned.

Stateless by design

There's no database and no server-side session: the client holds the game state and posts it back with every request. That's partly simplicity and partly practical — this runs on free-tier hosting that spins containers down when idle, and a stateless design means a cold restart never loses a game in progress.
